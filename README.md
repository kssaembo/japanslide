# 한글학교 교육을 위한 AI 활용 첫걸음

20장 / 60분의 인터랙티브 웹 연수. 기존 AI 채용 면접 서비스와 **별도 프로젝트**입니다. React·TypeScript·Vite·Tailwind·Motion·Lucide·Supabase 기반입니다. 2일차 자료도 같은 구조에서 새 강의로 추가할 수 있습니다.

## 처음 사용할 때

1. 이 폴더를 새 GitHub 저장소에 업로드합니다. 기존 투표 서비스 저장소를 덮어쓰지 않습니다.
2. Vercel에서 새 프로젝트로 가져옵니다. Framework: Vite, Build: `npm run build`, Output: `dist`. Node 22 권장.
3. Supabase SQL Editor에서 `supabase/001_presentation.sql`을 실행합니다. 기존 interview 테이블을 변경하지 않습니다.
4. Supabase Authentication → Users에서 기존 강사 계정의 UUID를 복사하고 다음 SQL을 별도로 실행합니다.

```sql
insert into public.ha_admins(user_id) values('실제-사용자-UUID') on conflict do nothing;
```

5. Vercel Settings → Environment Variables에 다음 두 값을 등록하고 **Redeploy**합니다.

| 변수 | 값 |
|---|---|
| `VITE_SUPABASE_URL` | Supabase 프로젝트 URL |
| `VITE_SUPABASE_ANON_KEY` | Supabase anon 또는 publishable key |

브라우저에는 공개 키만 사용합니다. service_role 키는 넣지 않습니다. 기존 투표 서비스와 같은 Supabase 프로젝트를 써도 됩니다. ha_* 테이블과 ha-media 저장소가 별도로 생성됩니다.

6. Supabase Authentication → URL Configuration에 Vercel 주소를 Site URL / 허용 Redirect URL로 등록합니다. 이 버전은 이메일·비밀번호 로그인을 사용합니다. 강사 계정은 Supabase에서 미리 생성합니다.
7. 웹의 **강사 편집**에서 로그인합니다. **초기 강의 가져오기** → 이 압축파일의 `seed/day1-private.json` 선택 → **저장** → **게시**합니다. 이 과정으로 상세 발표자 노트도 비공개 DB에 저장됩니다.
8. 시연 탭에서 기존 AI 채용 면접의 실제 공개 Vercel 주소를 등록하고 다시 저장·게시합니다. 아직 주소가 없으면 완성된 사전 제작 예시로 진행할 수 있습니다.

서버 설정 전에도 기본 자료는 실행됩니다. ‘로컬 편집 체험’은 이 브라우저에만 저장하며 실제 인증·공동 편집·서버 게시와 다릅니다. 초기 패키지 JSON을 가져오면 로컬에서도 전체 발표자 노트를 볼 수 있습니다. 패키지를 가져오기 전 노트는 비어 있습니다.

## 화면 주소

| 주소 | 기능 |
|---|---|
| `/` | 연수 입장, 발표·자료 읽기 선택 |
| `/present/day1` | PC·프로젝터 발표 |
| `/read/day1` | 청중 모바일 자료 |
| `/edit/day1` | 인증된 강사 편집 |
| `/notes/day1` | 인증된 강사 전용 노트 창 |
| `/edit/day1?demo=1` | 서버 설정 전 로컬 편집 체험 |

프레젠테이션은 ← → 이동, Space 단계 공개, Home/End 첫/끝 슬라이드, 전체 화면 버튼 및 ESC 종료를 지원합니다. 외부 시연은 새 탭으로 열립니다. 현재 위치는 같은 브라우저의 탭 세션에 저장됩니다.

프로젝터에는 발표 모드만 표시하고 ‘발표자 창’을 노트북 화면으로 이동하세요. Windows는 Win+P → 확장 모드를 사용합니다. 화면 복제 상태에서는 창을 옮겨도 노트가 프로젝터에 보일 수 있습니다. 노트 창에는 현재·전체 시간, 이전/다음 및 직접 이동 기능이 있습니다. 노트 창과 발표 화면은 같은 브라우저에서 연결됩니다.

## 편집 방법

왼쪽 목록에서 슬라이드 선택 → 오른쪽 내용을 입력하면 가운데 미리보기가 즉시 바뀝니다.

- 제목·부제·메시지·본문·카드·출처·시연 프롬프트를 직접 수정합니다.
- 본문의 문단은 빈 줄로 구분합니다. HTML을 입력해도 실행하지 않고 글자로 표시합니다.
- 이미지와 영상은 업로드 버튼으로 교체합니다. 이미지는 최대 긴 변 1600px WebP로 변환해 저장합니다. JPG·PNG·WebP만 허용하며 SVG/실행파일은 거부합니다.
- 이미지 확대·가로/세로 크롭 위치를 조절할 수 있습니다. 영상은 MP4/WebM 직접 파일이며 최대 25MB입니다. 외부 영상은 직접 HTTPS 파일 주소를 쓰거나 시연 링크로 등록합니다.
- 슬라이드 아래 ↑ ↓, 복제, 삭제로 구성을 바꿉니다. 최소 1장은 유지합니다.
- 노트 탭은 실제 설명·강조·질문·사례·전환 멘트이며 공개 게시 데이터에 포함되지 않습니다.
- **저장**은 관리자 임시 저장본만 변경합니다. **게시**가 청중 자료를 변경합니다. 저장되지 않은 상태에서는 게시할 수 없습니다.
- 수정 이력에서 이전 내용을 편집 화면으로 복원한 후 저장하면 새로운 수정본이 됩니다. 게시 여부는 별도로 결정합니다.
- 저장하지 않은 변경 내용은 같은 브라우저에 복구본으로 남습니다. 다음 방문 때 복구/버리기를 선택합니다. 공유 PC에서는 로그아웃 전 저장하고 복구본을 버리세요.
- 다른 관리자 창에서 먼저 저장하면 `revision conflict`로 덮어쓰기를 막습니다. 새로고침으로 최신본을 불러온 후 필요한 변경을 다시 적용하세요.

강의 탭의 메타데이터와 표지 슬라이드 제목은 독립 필드입니다. 연수명을 바꾸면 표지 제목도 함께 수정하세요.

## 2일차 추가

‘새 연수 추가’ → `day2` 입력 → 필요하면 기존 자료를 초기 패키지로 가져오거나 슬라이드 추가·삭제·수정 → 저장·게시. `/present/day2`와 `/read/day2`로 열며, 첫 화면에는 서버에 게시된 추가 강의가 표시됩니다. 새 강의의 시작 화면은 기본 1일차 복사본이므로 수정 후 게시하세요.

## 오프라인 준비

1. 발표할 PC에서 배포 주소를 열어 Service Worker 설치를 기다립니다.
2. 발표 화면의 **게시 버전 확인** 버튼으로 최신 v번호를 확인합니다.
3. **오프라인 준비**를 누릅니다. 게시된 데이터와 정적 삽화, 업로드 미디어를 캐시합니다. 실패한 미디어 수가 0인지 확인하세요.
4. 인터넷을 끊고 새로고침, 슬라이드 이동, 이미지 열기와 사전 제작 예시 표시를 리허설합니다.

앱 셸은 빌드 버전, 미디어는 강의 게시 버전별로 캐시합니다. 외부 서비스·실시간 투표·실시간 AI 시연에는 인터넷이 필요합니다. 인증 및 비공개 노트는 오프라인 제공을 보장하지 않습니다. 브라우저 저장공간을 지우거나 시크릿 모드를 닫으면 캐시가 사라질 수 있습니다. 강의 당일 새 버전을 확인한 뒤 준비하세요. 자동으로 새 발표 자료로 전환하지 않습니다.

## 콘텐츠 및 미디어

- 기본 공개 자료: `src/content/day1.json`
- 상세 비공개 노트 포함 초기 패키지: `seed/day1-private.json` (정적 `public/` 폴더에 넣지 않습니다)
- 타입과 디자인: `src/types.ts`, `src/SlideView.tsx`, `src/styles.css`
- AI 제작 삽화: `public/assets/chuseok-classroom.webp` (가상 인물)
- 시연 8종은 내용 데이터의 demos로 관리하고 관리자 시연 탭에서 링크·파일·대체 예시를 교체합니다.

실제 생성 영상은 이 패키지에 포함하지 않았습니다. 영상 제작안과 대체 설명을 제공하고, 강사가 만든 MP4/WebM을 업로드해 사용할 수 있습니다. 실제 학생·행사 정보는 사용하지 않았습니다. AI API·TTS API는 호출하지 않습니다.

## 개발 및 검증

```sh
npm ci
npm run dev
npm test
npm run test:db
npm run build
```

DB 테스트는 PGlite에 Supabase의 auth/storage 핵심 구조를 모의해 SQL 및 권한·RLS·트랜잭션을 검증합니다. 실제 Supabase 네트워크·Storage API 전체 검증을 대신하지 않습니다. 현장 점검은 `docs/CHECKLIST.md`, 수행 결과는 `docs/TEST_REPORT.md`를 보세요.
