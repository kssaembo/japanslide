# 기존 Supabase에 슬라이드 연결

1. 기존 AI 신입 선생님 Supabase 프로젝트 → SQL Editor에서 supabase/migrations/001_slide_cloud.sql을 실행합니다. interview_* 테이블은 변경하지 않습니다.
2. interview_admins의 기존 관리자 계정은 슬라이드 관리자 목록으로 복사됩니다. 해당 계정이 없으면 SQL 마지막 줄의 예시로 Auth Users의 UUID를 ha_slide_admins에 등록하세요. 이메일이나 비밀번호가 아닌 Auth 사용자 UUID입니다.
3. 슬라이드 Vercel 프로젝트 Settings → Environment Variables에 두 값을 등록합니다.
   - VITE_SUPABASE_URL: 기존 프로젝트 URL
   - VITE_SUPABASE_ANON_KEY: 기존 anon 키 또는 publishable 키
   - Production과 Preview(필요 시 Development)에 적용하고 재배포합니다. service_role 키는 넣지 않습니다.
4. 슬라이드 /edit/day1에서 기존 Supabase 계정 이메일·비밀번호로 로그인합니다. 처음에는 초기 자료가 표시됩니다.
5. 기존 수정본을 JSON 가져오기로 불러오거나 ‘기존 로컬 편집본 가져오기’를 누릅니다. 저장할 때 JSON 안의 이미지·영상과 로컬 파일을 ha-slide-media에 업로드하고, 문서를 ha_slide_drafts에 저장합니다. 게시 버튼으로 ha_slide_published를 갱신합니다.
6. 다른 기기 또는 시크릿 창에서 /read/day1을 열어 같은 게시본을 확인합니다. 이미 접속한 기기는 새로고침하거나 발표 화면의 ‘게시본 새로 확인’을 누릅니다.

이미지·영상: 비공개 ha-slide-media 버킷. 관리자는 미리보기 가능, 일반 사용자는 게시본에서 참조하는 파일만 서명 URL로 읽을 수 있습니다. 임시 저장본·발표자 노트·수정 이력은 관리자만 조회합니다. 임시 저장과 게시가 분리됩니다.

큰 복구본·오프라인 게시본은 IndexedDB를 사용하므로 기존 localStorage 한도를 피합니다. 환경변수를 비워두면 로컬 편집으로 작동합니다. 기존 브라우저 자료를 자동 삭제하지 않습니다. SQL 적용 후 콘텐츠 가져오기→저장→게시를 해야 다른 기기에서 볼 수 있습니다.

동시에 두 창에서 저장하면 수정 충돌을 표시합니다. 이 경우 JSON 백업 후 서버 편집본을 다시 여세요. 업로드 중 오류가 있으면 게시 성공으로 표시하지 않습니다. 실패한 업로드는 관리자용 버킷에 남을 수 있으며 자동 삭제하지 않습니다.

## 발표 리모컨

발표 모드에서 다음 입력은 카드 1→카드 2→…→슬라이드 이미지→다음 슬라이드로 진행합니다. 이미지 전용은 이미지 1→2→3→다음 슬라이드입니다. 이미지+URL은 이미지를 확대하고 다음 입력 시 다음 슬라이드로 이동합니다. URL은 버튼을 직접 눌러 열며 리모컨이 자동으로 외부 사이트를 열지는 않습니다.

다음: PageDown·오른쪽/아래 방향키·Space·Enter. 이전: PageUp·왼쪽/위 방향키·Backspace. ESC: 현재 팝업 닫기. 입력창을 편집 중이면 리모컨 동작을 실행하지 않습니다. 하단 다음·이전 버튼과 발표자 노트 창의 다음·이전도 같은 순서로 진행합니다.

리모컨이 다른 키나 마우스 신호를 보내는 제품이면 실제 노트북에서 확인이 필요합니다. 일반적인 PageDown/PageUp 방식은 지원합니다.

## 연결 확인에 필요한 정보

연결값은 채팅에 보내지 않고 Vercel에 직접 입력해도 됩니다. 문제가 있으면 SQL 오류 메시지 또는 브라우저 오류 메시지를 전달하세요. 비밀번호·service_role 키는 제공하지 마세요.

실제 Supabase와 Vercel 환경값은 이 개발환경에 없으므로 실제 로그인·업로드·다중 기기 동기화는 배포 후 확인해야 합니다. 기존 테스트용 초기 자료는 유지합니다.
